## B. Fase 3 — peta kebutuhan → implementasi (tanpa tabel paralel)

1. **PIC Meja & PIC QC membaca konteks** → blok **Konteks analisis** (baca saja; `AnalysisContext`): keluhan/request/berat customer (rujukan; tidak pernah mengisi berat penguji), komponen lama atas→bawah (+total), QC awal, uji fondasi — semuanya dari **satu** endpoint Catatan Komponen. Tampil di Meja, aplikasi PIC Bahan, dan di dalam lembar Racikan rencana.
2. **Diagnosis + racikan fondasi/lapisan** → seksi baru **`PLAN_RACIKAN` ("Racikan rencana")** di Catatan Komponen (bentuk sama dengan `AFTER`, satu normalizer): fondasi + lapisan **atas→bawah**, tiap lapisan dipertahankan/diperbaiki/diganti, bahan (katalog/manual/tidak diketahui), ketebalan, **total tinggi** (hanya dari yang diketahui; ada yang kosong = "belum lengkap", bukan 0; KEEP/REPAIR tanpa tebal mewarisi catatan awal dan ditandai "dari catatan awal"). **Rencana dan hasil aktual terpisah**: `PLAN_RACIKAN` vs `AFTER`; perbandingan per lapisan (sesuai/berbeda: tindakan·bahan·tebal; hanya-rencana/tidak-direncanakan) + selisih total — hanya bila keduanya tercatat. Narasi diagnosis tetap di wizard Diagnosis (sumber yang sudah ada); tidak disalin.
3. **Katalog menampilkan atribut yang ada** → snapshot katalog kini memuat **supplier (Material.vendor)** dan **kelompok (itemGroup)** bila ada; tampil kode, nama, satuan, supplier, kelompok. **Densitas & ketebalan katalog tidak ada di master Material → tidak ditampilkan dan tidak dikarang** (muncul otomatis bila kelak ada di snapshot). Bahan manual ("belum terhubung katalog") dan "Tidak diketahui" tetap sah. Entri lama tanpa atribut baru tidak memicu versi baru hanya karena snapshot diperkaya.
4. **Layanan Sales tetap acuan** → wizard Diagnosis hanya-baca (tidak ada pilihan layanan teknis; dijaga tes).
5. **PIC Bahan per pekerjaan (Febri/Ucok, Ferdy)** → command & tabel jalur pengerjaan **yang sama** (`setBuildMaterialOperator`, `recordBuildMaterials`, `production_run_build_settings_v2`, `production_build_material_records_v2`) kini juga untuk LAYANAN (SEWA tidak). Untuk LAYANAN: **hanya pemakaian aktual** (racikan teks ditolak `BUILD_RACIKAN_NOT_APPLICABLE_LAYANAN` — racikan = Catatan Komponen; penentu tercatat aktornya); BOM lewat command resmi yang sudah ada (`POST /production-planning/plans/:id/bom`, izin `UNIT_MATERIAL_WRITE`). Antrean PIC Bahan memuat pekerjaan LAYANAN yang ditugaskan; kartu Run memuat `materialPic`.
6. **Dokumentasi tidak wajib** pada analisis/racikan → `PLAN_RACIKAN` tanpa minimal media (foto opsional, maks 8); tahap 5 tidak menuntut dokumentasi baru (dijaga tes + QA: tersimpan dengan 0 media).
7. **Reuse sumber catatan komponen & BOM; koreksi berversi, konflik, replay** → append-only versi, koreksi wajib alasan, `expectedVersion` (409 `COMPONENT_VERSION_CONFLICT`), `Idempotency-Key` (replay = respons sama), "tanpa perubahan = tanpa versi baru". Tidak ada tabel baru untuk racikan/PIC Bahan LAYANAN (dijaga tes statis).
8. **Pemilihan bahan tidak memotong stok; pemakaian hanya dari bahan sah diserahkan; stok keluar tidak ganda; retur utuh** → rencana/aktual tidak menyentuh stok/BOM/reservasi/issue/retur (hitungan baris di tes + SQL QA: 0/0/0/0). Pemakaian PIC Bahan dibatasi pada bahan yang diserahkan Gudang (tak boleh melebihi); stok keluar tetap hanya saat Gudang menyerahkan. **Anti hitung ganda dua arah:** bila PIC Bahan ditugaskan, bukti Meja tahap 6/7 menolak bahan (`STEP_MATERIAL_BY_MATERIAL_PIC`), PIC Bahan ditolak bila bukti Meja sudah memuat bahan; Meja menunggu (`USAGE_NOT_RECORDED`) sampai pemakaian tercatat (mencegah "retur penuh palsu"). Sisa = diserahkan − pemakaian, dihitung sekali. **Tanpa PIC Bahan ditugaskan: perilaku lama persis** (tidak ada blok baru).
