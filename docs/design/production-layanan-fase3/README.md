## B. Fase 3 — peta kebutuhan → implementasi (tanpa tabel paralel)
1. **Konteks analisis** (baca saja, `AnalysisContext`): keluhan/request/berat customer (rujukan), komponen lama atas→bawah (+total), QC awal, uji fondasi — satu endpoint Catatan Komponen. Tampil di Meja, aplikasi PIC Bahan, dan lembar Racikan rencana.
2. **Racikan rencana** = seksi **`PLAN_RACIKAN`** (bentuk = `AFTER`, satu normalizer): fondasi + lapisan atas→bawah, dipertahankan/diperbaiki/diganti, bahan (katalog/manual/tidak diketahui), ketebalan, **total tinggi** (kosong = "belum lengkap", bukan 0; KEEP mewarisi catatan awal, ditandai). Terpisah dari hasil aktual (`AFTER`); perbandingan per lapisan + selisih total hanya bila keduanya tercatat. Aktor penentu tercatat.
3. **Katalog**: snapshot memuat supplier (`Material.vendor`) + kelompok (`itemGroup`) bila ada. Densitas/ketebalan tidak ada di master Material → tidak ditampilkan/dikarang. Manual & "Tidak diketahui" tetap sah.
4. **Layanan Sales tetap acuan** (wizard Diagnosis hanya-baca; dijaga tes).
5. **PIC Bahan per pekerjaan** (Febri/Ucok = **satu orang**; Ferdy petugas lain — tidak ada perubahan akun): command & tabel jalur pengerjaan yang sama, kini juga untuk LAYANAN (SEWA tidak):
   - **Penugasan** `setBuildMaterialOperator` (izin penjadwalan; tidak berubah).
   - **BOM rencana (baru, UI + route)** `POST /production-v2/runs/:runId/build/plan-bom` → memanggil `setPlannedBOM` (command planning yang SAMA: revisi rencana, Idempotency-Key, tolak bila bahan sudah diserahkan/permintaan ambil aktif, reservasi dilepas bila BOM berubah) lewat hook `authorize` opsional: **hanya PIC Bahan yang ditugaskan pada pekerjaan itu** (atau ADMIN/OWNER via `PRODUCTION_EXECUTE_ANY`). Lead, Gudang/Meja, PIC pekerjaan lain, dan pemanggil tanpa PIC ditugaskan → 403. Endpoint planning lama (`/plans/:id/bom`) tidak diubah dan tidak ada penulis BOM kedua.
   - **Pemakaian aktual** `recordBuildMaterials` (hanya dari bahan yang diserahkan; racikan teks ditolak untuk LAYANAN).
   - **UI aplikasi PIC Bahan:** bagian PIC Bahan + **rantai bahan** (racikan Meja/QC → BOM rencana → diserahkan Gudang → dipakai; empat catatan terpisah ditautkan per bahan katalog; "Belum dicatat/Belum diserahkan" bila kosong; penanda ketidaksesuaian ringan), lembar **Rencana Bahan (BOM)** (acuan racikan + "Tambah ke BOM", cari katalog, revisi, terkunci setelah serah, peringatan pelepasan reservasi), lembar **Catat Bahan Dipakai**. Pesan penolakan PIC dari server tampil apa adanya.
6. **Dokumentasi tidak wajib** pada analisis/racikan.
7. **Pesan Sales ("Salin Pesan")** kini memuat **ringkasan racikan rencana vs hasil aktual** (fondasi, tiap lapisan, total tinggi + selisih); data kosong = "Belum dicatat". LAYANAN selalu menampilkan bagian ini; jenis lain hanya bila ada catatan. Diuji unit; tampilan pesan di UI tidak diklik karena tombol laporan nonaktif sampai produksi selesai ("BELUM SIAP").
8. **Stok & retur:** rencana racikan, BOM rencana, dan pemakaian aktual **tidak** menulis stok/reservasi; stok keluar hanya saat Gudang menyerahkan; sisa = diserahkan − pemakaian (dihitung sekali; QA E6.5). Anti hitung ganda dua arah: PIC Bahan ditugaskan → bukti Meja tahap 6/7 menolak bahan; Meja menunggu pemakaian tercatat (`USAGE_NOT_RECORDED`). Tanpa PIC Bahan ditugaskan: perilaku lama persis.
