## Yang dibangun
1. **Corner diperlukan.** Server membangun kartu "Permintaan Sales untuk Corner" (`loadCornerView`, `lib/domain/productionCorner.js`) dari item pesanan + catatan pesanan APA ADANYA: ganti kain, motif, warna, permintaan khusus. Bila ganti kain diminta tetapi motif/warna tidak tertulis → **"Perlu konfirmasi Sales"** (tidak menebak). Untuk Run berkebijakan V2, **Mulai Jahit** (tahap 10) mewajibkan: centang sudah memeriksa permintaan, kain lama dipakai kembali / kain baru dipasang, sesuai/ada perbedaan (+catatan), hasil konfirmasi Sales bila "Perlu konfirmasi" dan kain baru, serta ≥1 foto/video proses. **Jahit Selesai** (tahap 11) mewajibkan pekerjaan Corner, catatan perbedaan atau "tidak ada perbedaan", checklist, dan foto/video hasil. Run V1/NULL memakai kontrak lama (tidak berubah).
2. **Corner tidak diperlukan.** Mengikuti keputusan Lead (`cornerRequired=false` + alasan + pemutus). Status "Corner tidak berlaku" dengan alasan; tidak ada aktivitas/bukti Corner; PIC Meja menyelesaikan. Mode adaptasi: alasan "tahap Corner dilewati sesuai kebijakan".
3. **Dokumentasi akhir.** `buildDocumentationSequence`: sebelum bongkar → isi kasur lama → racikan → hasil rakitan → uji QC → kain/Corner → hasil jadi & siap kirim. Dihitung dari matriks dokumentasi + Catatan Komponen (tanpa menyalin berkas); sumber Meja/QC/Corner/Driver/Gudang/Dokumenter dikenali; kategori tak berlaku (mis. Corner) diberi alasan, bukan foto buatan. Tampil di Aplikasi Dokumentasi, laporan.
4. **Selesaikan Produksi** (`POST /runs/:id/finish`, pratinjau `GET .../finish-preview`). Adaptasi: perilaku lama (tahap dilewati SKIPPED jujur, tanpa custody/foto/jurnal). Non-adaptasi (baru): pratinjau memeriksa putusan QC sesuai kebijakan yang dipin Run, keputusan Corner, tahap berjalan, retur sisa bahan; aksinya = konfirmasi tahap 12 yang sudah ada (foto hasil jadi wajib) → **satu** penawaran barang jadi ke Gudang + **satu** event laporan; idempoten (kunci sama = respons sama); dua penyelesaian bersamaan: satu menang, lainnya 409. **Siap Kirim** baru setelah Gudang menerima barang jadi, dan itu ditahan selama retur sisa PENDING (`RETURN_PENDING`); job Delivery tepat satu dibuat oleh jalur yang sudah ada saat Siap Kirim. Tidak ada custody/penerimaan/foto/jurnal palsu.
5. **Status terpadu** (`lib/domain/productionLifecycle.js` → `cornerAndLifecycleOf`): satu kosakata (Menunggu QC, Rework, Menunggu dikerjakan Corner, Sedang di Corner, Siap diselesaikan, Menunggu Gudang menerima barang jadi, Siap Kirim, …) di Meja, Corner, Dokumentasi, Unit 360, kartu Status Produksi, laporan. Siap Kirim hilang dari papan/backlog Rencana aktif (filter lama) tetapi tetap ada di Unit 360/laporan.
